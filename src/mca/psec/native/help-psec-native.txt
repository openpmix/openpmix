[unverified-peer]
A process at %s asked to connect to this PMIx server using the "native"
security mechanism, claiming to be uid %lu. The operating system could
not confirm who owns that connection, so the request was refused:

  Reason:  %s

The native mechanism confirms a peer's identity by asking this host's
kernel which user owns the far end of the connection, so it serves only
peers on this host (and in the same network namespace). A peer
elsewhere uses a mechanism that works across hosts:

  * ssl - the peer presents an X.509 certificate issued by a CA this
    server trusts (PMIx configured --with-openssl; see the psec_ssl_*
    MCA parameters), and selects it with PMIX_MCA_psec=ssl; or

  * munge - PMIx configured --with-munge, with munged running on every
    node.
#
[foreign-group]
A process owned by uid %lu asked to connect to this PMIx server as a
tool, claiming group id %lu. That user does not belong to that group, so
the request was refused.
